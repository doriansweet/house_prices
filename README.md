# House Prices Regression

Проект решает задачу регрессии из соревнования Kaggle
[House Prices: Advanced Regression Techniques](https://www.kaggle.com/competitions/house-prices-advanced-regression-techniques).
Цель — предсказать стоимость жилых домов (`SalePrice`) по числовым и
категориальным характеристикам.

Проект включает EDA, обработку пропусков, Feature Engineering, сравнение
классических моделей, бустингов и нейронной сети, кросс-валидацию и создание
Kaggle submission. Все модели и параметры задаются в `config.yaml`.

## Основной результат

Лучшая отдельная модель на текущем этапе — CatBoost:

| Модель | Лучшие параметры | CV RMSE | CV std |
|---|---|---:|---:|
| CatBoost | `depth=6`, `iterations=700`, `learning_rate=0.03`, `l2_leaf_reg=3` | **0.12436** | 0.01840 |

Итоговый Kaggle score: 0.12402.

## Результаты моделей

Все модели оценивались на одинаковых пяти фолдах. Чем меньше CV RMSE, тем
лучше результат.

| Модель | Параметры лучшего запуска | CV RMSE | CV std |
|---|---|---:|---:|
| Linear Regression | — | 0.16353 | 0.03330 |
| Ridge | `alpha=10` | 0.13386 | 0.03195 |
| Lasso | `alpha=0.0005` | 0.13313 | 0.03610 |
| ElasticNet | `alpha=0.0005`, `l1_ratio=0.7` | 0.13213 | 0.03494 |
| KNN | `n_neighbors=10`, `weights=distance`, `p=2` | 0.15933 | 0.01350 |
| Decision Tree | `max_depth=5`, `min_samples_leaf=3` | 0.18536 | 0.02093 |
| Random Forest | `max_depth=15`, `min_samples_leaf=3` | 0.14021 | 0.01766 |
| XGBoost | `max_depth=3`, `n_estimators=700`, `learning_rate=0.03` | 0.12543 | 0.01909 |
| LightGBM | `num_leaves=15`, `n_estimators=700`, `learning_rate=0.03` | 0.12979 | 0.01784 |
| CatBoost | `depth=6`, `iterations=700`, `learning_rate=0.03` | **0.12436** | 0.01840 |
| DNN | `[256, 128, 64]`, BatchNorm, Dropout 0.2 | 0.14468 | 0.03514 |

Регуляризованные линейные модели существенно превосходят обычную линейную
регрессию. KNN плохо работает в разреженном пространстве после One-Hot
Encoding. Одно решающее дерево переобучается, Random Forest улучшает его
результат, а лучшие метрики показывают градиентные бустинги.

## EDA

Исследовательский анализ находится в `eda.ipynb` и включает:

- размер выборки, типы данных и описательные статистики;
- анализ количества и доли пропусков;
- распределение `SalePrice`;
- корреляции признаков с целевой переменной;
- зависимости цены от площади, качества, года постройки и других признаков;
- сравнение цен по районам (`Neighborhood`).

Основные наблюдения:

- `SalePrice` имеет выраженную правостороннюю асимметрию;
- наиболее сильная связь с ценой наблюдается у `OverallQual`, `GrLivArea`,
  `GarageCars`, `GarageArea` и `TotalBsmtSF`;
- многие пропуски означают отсутствие объекта, например бассейна, гаража,
  подвала или камина;
- район дома заметно связан с его стоимостью.

## Предобработка

Предобработка выполняется внутри sklearn `Pipeline`, поэтому imputer, encoder
и scaler обучаются только на обучающей части каждого фолда.

Используются отдельные профили для разных типов моделей:

- линейные модели, KNN и DNN: заполнение пропусков, One-Hot Encoding и
  стандартизация числовых признаков;
- деревья и бустинги: заполнение пропусков и One-Hot Encoding без
  стандартизации;
- DNN дополнительно получает плотную матрицу после кодирования.

Предметная обработка пропусков различает:

- отсутствие объекта: категория `Absent` или числовой ноль;
- неизвестное значение: медиана для числового признака или наиболее частая
  категория.

Проверенные варианты:

| Заполнение | Scaling | Encoding | Ridge CV RMSE |
|---|---:|---|---:|
| simple | да | One-Hot | 0.13385 |
| semantic | да | One-Hot | 0.13386 |
| semantic | нет | One-Hot | 0.13903 |
| semantic | да | Ordinal | 0.14330 |

Для итогового pipeline выбрано предметное заполнение. Для линейных моделей
оставлены стандартизация и One-Hot Encoding.

## Feature Engineering

Feature Engineering разделён на независимо включаемые группы:

- `aggregates`: общая площадь, количество ванных комнат, возраст дома,
  площадь веранд;
- `interactions`: произведения качества и площади, квадраты, отношения;
- `logs`: логарифмы признаков с длинным правым хвостом;
- `indicators`: наличие гаража, подвала, камина, бассейна, второго этажа и
  других объектов.

| Группа | Ridge CV RMSE |
|---|---:|
| Без дополнительных признаков | 0.14609 |
| Только агрегаты | 0.14619 |
| Только взаимодействия | 0.14113 |
| Только логарифмы | 0.13519 |
| Только индикаторы | 0.14361 |
| Все группы | **0.13385** |

Самостоятельно наиболее полезными оказались логарифмические преобразования.
Совместное использование всех групп улучшило Ridge примерно на 8.4% по
сравнению с вариантом без Feature Engineering.

## Валидация

Используется `KFold`, поскольку решается задача регрессии:

```yaml
validation:
  n_splits: 5
  shuffle: true
  scoring: neg_root_mean_squared_error
```

`random_state=42` фиксирует разбиение и позволяет честно сравнивать
эксперименты. `StratifiedKFold` не используется, поскольку целевая переменная
не является классом.

Runner также умеет:

- обучить лучшую модель на всей обучающей выборке;
- обучить лучшие CatBoost, XGBoost и LightGBM отдельно на каждом из пяти
  фолдов;
- усреднить test-прогнозы fold-моделей;
- построить равновзвешенный или взвешенный ансамбль бустингов.

## DNN

Нейронная сеть реализована на PyTorch в `src/dnn.py` и совместима со sklearn
API. Проверены две архитектуры:

```text
Input → 128 → 64 → Output
Input → 256 → 128 → 64 → Output
```

Текущая конфигурация использует:

- `ReLU`;
- `BatchNorm`;
- `Dropout(0.2)`;
- Adam;
- cosine scheduler;
- MSE loss;
- 100 эпох;
- batch size 64.

На небольшом табличном датасете DNN уступает бустингам, однако выполняет
требование проекта и остаётся доступной для дальнейших экспериментов.
